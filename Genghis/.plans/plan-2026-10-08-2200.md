### Step 0: Bug Identification [COMPLETED-2026-10-08 22:00]

**File:** `Genghis\Genghis-Class-CoverMission.cs`  
**Method:** `turnOffRegularDisplay_listPositionCurrentCoverAircraft` (line ~3036-3045)

**Bug Description:**
The `turnOffRegularDisplay_listPositionCurrentCoverAircraft` method was unconditionally calling `Console.WriteLine("CoverDisplay: OFF (turnOffRegularDisplay)...")` at the end of the method, even when the display wasn't actually turned off (when the boolean `ret` parameter was `false`). This meant that even if no display was turned off (because the cover aircraft was already released or the display wasn't active), the log message would still print, suggesting the display was turned off when it actually wasn't.

This bug is related to the previously documented 10-minute "final run" timeout issue (documented in .clinerules-long):
> A stale timeout armed at 18:38:34 (player bail-out) fired at 18:48:34 — ten minutes later — and silently called `turnOffRegularDisplay`, killing the position display that a `<cover` re-checkout at 18:40:13 had just re-armed.

**Analysis:**
- The existing fix from 2026-10-06 addressed the stale timeout by guarding with `if (!coverAircraftAirGroupsActive.ContainsKey(airGroup)) return;` and removing the `turnOffRegularDisplay` call from the timeout callback
- However, the `turnOffRegularDisplay` method itself still had the unconditional logging issue
- This could cause misleading log output and potential premature display shutdown

### Step 1: Bug Fix [COMPLETED-2026-10-08 22:00]

**File:** `Genghis\Genghis-Class-CoverMission.cs`  
**Line:** 3043

**Change Made:**

Before:
```csharp
if (mainmission.ON_TESTSERVER) Console.WriteLine("CoverDisplay: OFF (turnOffRegularDisplay) for " + player.Name());
```

After:
```csharp
if (mainmission.ON_TESTSERVER && ret)
    Console.WriteLine("CoverDisplay: OFF (turnOffRegularDisplay) for " + player.Name());
```

**Rationale:**
This ensures the "CoverDisplay: OFF" message is only logged when the display was actually turned off (when `ret` is `true`), preventing misleading log output and ensuring the display state is accurately reported.
