## Root Cause (analysis completed in prior turn)

File: `E:\Cliffs-of-Dover\TWC-campaigns-github\TWC_Mission_Server\Genghis\Genghis-Class-CoverMission.cs`
(TOTAL 12662 lines; recursion spans lines 6456–7078)

1. **Recursive re-arm at the top of every call** (line 6514):
   `Timeout(actual_delay, () => keepAircraftOnTask_recurs(...))` schedules the
   next heartbeat tick *before* the current iteration's main logic runs.
2. **The body itself removes/deactivates the group mid-iteration:**
   - `coverAircraftAirGroupsActive.Remove(airGroup)` + `forgetAirGroup(...)` at
     lines 6528/6529 (`numAC == 0` path) and 6555/6556 (released path),
   - `EscortMakeLand(airGroup, ...)` at lines 6595–6637 (player crashed / left /
     too distant / aircraft not allowed cover).
3. The already-scheduled `Timeout` then fires holding the stale `airGroup`
   reference; the next iteration (or the *same* iteration reaching its
   `setTask` calls after the group was deactivated) invokes
   `airGroup.setTask(...)` on a dead group → `NullReferenceException`.

**Existing guards that prove the correct pattern:**
- Entry guard at 6497–6501 (`!coverAircraftAirGroupsActive.ContainsKey(airGroup)` →
  `EscortMakeLand` + `return`) — but it runs *after* the 6514 re-arm and does not
  protect the current iteration's later `setTask` calls.
- `EscortMakeLand` itself (line 8662):
  `if (airGroup == null || !coverAircraftAirGroupsActive.ContainsKey(airGroup)) return;`
- The 10-min final-run stale-timer guard at line 6618.

**Unguarded `airGroup.setTask(...)` call sites inside the recursion:**
- line 6900 — `airGroup.setTask(AiAirGroupTask.DEFENDING, playerAirGroup);`
- line 6911 — `airGroup.setTask(task, attackingAirGroup);`
- line 6980 — `airGroup.setTask(AiAirGroupTask.DEFENDING, playerAirGroup);`
- line 7069 — `airGroup.setTask(task, tasktarget);`

`coverAircraftAirGroupsActive` is the single source of truth for alive cover
groups (see .clinerules-long); every `setTask` must be gated on it.

## Planned Changes (single file: Genghis\Genghis-Class-CoverMission.cs)

### Patch A — hard early-exit at top of recursion

After the existing `if (airGroup == null) { checkPlayerAirgroups(player); return; }`
(lines 6485–6489), ensure an early return when the group is no longer active
BEFORE `cdRtbProbe` / any further work:

```csharp
            //Single source of truth for alive cover groups.  If the group is no longer active it
            //was already removed/landed - do NOT touch it anymore, especially NOT via
            //airGroup.setTask() below, or we hit a NullReferenceException on a dead AiAirGroup
            //(KeepAircraftOnTaskRECURS stack trace, 2026-10-10 23:46:50).
            if (!coverAircraftAirGroupsActive.ContainsKey(airGroup))
            {
                return; //group is gone - nothing left to do for it
            }
```

(Keep the existing 6497–6501 `EscortMakeLand`+return block intact or fold it in —
must not double-land; the `EscortMakeLand` guard at 8662 makes either order safe.)

            //Only re-arm the heartbeat if this group is STILL active; otherwise a stale Timeout

                Timeout(actual_delay, () => keepAircraftOnTask_recurs(airGroup, task, aawpt, player, delay, heavyBomber, isStrikeAC, isPlayerStrikeAC, AltDiff_m, AltDiff_range_m, AltDiffBomber_m, AltDiffBomber_range_m, AltDiffPlayerEscort_m, AltDiffPlayerEscort_range_m));
