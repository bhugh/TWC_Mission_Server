# Plan: Fix SFTP Upload Filename Encoding (%20 → space)

**Date:** 2026-10-28 14:30  
**Mode:** ACT (implementation allowed after plan file is written)

## Goal
Fix the regression where SFTP uploads store filenames with literal `%20` instead of spaces (e.g., `TWIN%20GRANDSONS%20OF%20KHAN_BLUE_radar.txt` instead of `TWIN GRANDSONS OF KHAN_BLUE_radar.txt`). The remote server expects real spaces, matching the legacy FTP behavior.

---

## Root Cause Analysis

In `StbSr_UploadSSL` (`Genghis\Genghis-Class-StatsMission.cs`), the remote path is derived from the `ftp://` URI:

```csharp
string remotePath = serverUri.AbsolutePath;   // preserves %20
sftp.UploadFile(inputStream, remotePath, true);  // sends literal string to SFTP server
```

`Uri.AbsolutePath` keeps percent-encoding. The old FTP server decoded `%20` → space; SFTP (Renci.SshNet) does not — it uses the path string literally. All upload callers (radar, tacview, stats HTML) funnel through this single method, so one change fixes all.

## Change

Inside `StbSr_UploadSSL`, after the `remotePath` empty-check and before the `Console.WriteLine("SFTP UPLOAD: ...")`:

```csharp
        string remotePath = serverUri.AbsolutePath;
        if (string.IsNullOrEmpty(remotePath))
        {
            remotePath = "/";
        }
        // SFTP sends the remote path to the server literally.  Uri.AbsolutePath preserves
        // percent-encoding (e.g. %20), but the remote SFTP server expects the actual space
        // character - matching the legacy FTP behavior where the FTP server decoded %20.
        // Decode so %20 etc. become real characters in the stored filename.
        remotePath = Uri.UnescapeDataString(remotePath);
```

---

## Why This Is Safe / Correct

- `Uri.UnescapeDataString` turns `%20` → ` ` (and any other percent-encoded chars), giving the exact filename the server expects (`TWIN GRANDSONS OF KHAN_BLUE_radar.txt`).
- If `AbsolutePath` ever already returned a decoded space, `UnescapeDataString` is a harmless no-op.
- It's inside the existing `try/catch`; malformed `%` sequences are caught, logged, and return `false` rather than crashing.
- C#5-compliant: no string interpolation, `out var`, pattern matching, `?.`, `nameof`, or `var`. `Uri.UnescapeDataString` is a static `System` method available since .NET 2.0.
- Leading `/` (absolute remote path) is preserved — unchanged from prior behavior.
- `using System;` is already present at line 125.
