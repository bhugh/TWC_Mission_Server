# ASV Radar No-Display Fix — Detailed Implementation Plan

**Mode: PLAN** — No files will be edited here. This document is written for an ACT-mode worker to follow step by step.

---

## 1. Bug Summary

When you switch to ASV radar via Tab-4-4-5:
- The command is accepted and logged: `Air to Surface Vessel (Authentic) command received.`
- Magnification is tracked: `Aerial Radar: New Magnification: 2` / `Display magnification set to 2`
- **But no radar grid ever appears on screen.**
- **No errors appear in the log.**

Root cause: `ASVRadarAuthenticArray.display_recurs()` runs `calculateGrid(); displayGrid();` inside a `Task.Run(...)` with **no try/catch**. Inside `calculateGrid()`, the code casts actors to `AiGroundActor` without a null guard:

```csharp
string types = (actor as AiGroundActor).Type().ToString().ToLower() + ...
```

If any actor in `shipList` is not an `AiGroundActor` (e.g. it passes the `"ship"` filter via `InternalTypeName` only), `.Type()` is called on a `null` → `NullReferenceException`. Because this is inside `Task.Run` with no catch, the exception is unobserved: nothing is written to console/log, `displayGrid()` never runs, and `display_recurs()` just keeps re-scheduling itself forever. Result: magnification works, status messages work, but **zero grid lines reach the player.**

Same unguarded cast exists at lines 943–944 inside `ASVRadarAuthenticArray.calculateGrid()`.

## 3. C#5 Language Constraints (MUST FOLLOW)

The mission compiler uses `/langversion:5`. Do **not** use any of the following:
- String interpolation: `$"..."` → use string concatenation `"..." + var`
- Null-conditional operator: `?.`
- `out var`
- Pattern matching: `x is AiGroundActor y`
- `nameof(...)`

**Allowed/required idioms:**
- `as` + null check: `AiGroundActor ga = actor as AiGroundActor; if (ga != null) { ... }`
- String concatenation: `"prefix " + var.ToString()`
- `Console.WriteLine("...{0}...", var)`
- Named `out` variables
